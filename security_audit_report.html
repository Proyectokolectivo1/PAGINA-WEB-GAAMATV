warning Lectura Pública de Borradores vía API Supabase
Riesgo Medio
Componente: lib/supabase.js | Tabla: noticias
Al remover el filtro de publicado = true en el cliente de base de datos para corregir previsualizaciones del administrador, toda la lógica de filtrado pasó al frontend. Con la política RLS actual habilitando SELECT incondicional a la red pública (USING (true)), cualquiera con la clave anónima puede extraer borradores consultando directamente la API REST de Supabase.
verified_user Mitigación Sugerida (Aplicar en Supabase SQL)
Actualizar la política RLS de lectura en Supabase:
DROP POLICY IF EXISTS "select_public_noticias" ON noticias; CREATE POLICY "select_public_noticias" ON noticias FOR SELECT TO public USING (publicado = true OR auth.role() = 'authenticated');
info Divulgación de Metadatos en Artículos Privados
Riesgo Bajo
Componente: app/noticia/[slug]/page.js (generateMetadata)
La función generateMetadata no valida si la noticia recuperada está publicada, sirviendo información social (título, descripción, imagen de portada) de borradores si se conoce el slug.
verified_user Mitigación Sugerida
Validar el estado de publicación en la generación de metadatos:
if (!noticia || !noticia.publicado) { return { title: 'Noticia no encontrada | GaamaTV', description: 'GaamaTV — El Lente Editorial del Oriente Antioqueño.', } }
info Falta de Sanitización en Parámetro de Canal Twitch
Riesgo Bajo
Componente: app/api/twitch-status/route.js (API Proxy)
El parámetro de consulta channel se interpola directamente en el string de query de GraphQL para consultar la API de Twitch. Si el parámetro contiene comillas dobles o caracteres extraños, podría interferir con la estructura de la consulta GraphQL (inyección de GraphQL) o generar fallos de análisis de sintaxis en el servidor remoto de Twitch.
verified_user Mitigación Sugerida
Implementar validación estricta por expresión regular antes de procesar la solicitud:
if (!channel || !/^[a-zA-Z0-9_]{4,25}$/.test(channel)) { return Response.json({ live: false, error: 'canal inválido' }, { status: 400 }) }
