warning Lectura Pública Incondicional de Borradores
Riesgo Medio
Componente: lib/supabase.js | Tabla: noticias
Al remover el filtro de publicado = true en el cliente de base de datos para corregir errores de renderizado en el panel de administrador, toda la lógica de filtrado de noticias publicadas pasó al Frontend de Next.js en app/noticia/[slug]/page.js. Si bien esto soluciona el problema de visualización del administrador, la tabla noticias tiene una política RLS de SELECT configurada como TO public USING (true). Esto permite que cualquier usuario descargue directamente borradores enviando queries HTTP REST directamente al endpoint de Supabase usando la clave anónima del frontend.
verified_user Mitigación Sugerida (Aplicar en Supabase SQL)
Actualizar la regla RLS para la tabla noticias de modo que la lectura pública solo se permita si el artículo ya está publicado, o si el solicitante es un usuario autenticado (administrador):
DROP POLICY IF EXISTS "select_public_noticias" ON noticias; CREATE POLICY "select_public_noticias" ON noticias FOR SELECT TO public USING (publicado = true OR auth.role() = 'authenticated');
info Divulgación de Metadatos en Artículos Privados
Riesgo Bajo
Componente: app/noticia/[slug]/page.js (generateMetadata)
La función generateMetadata se encarga de servir las cabeceras Open Graph y de Twitter para previsualización social. Al no filtrar las noticias en base a su estado publicado, si alguien conoce o adivina el slug de una noticia borrador, el servidor generará y responderá exitosamente con los metadatos reales de la noticia (título, extracto, imagen), revelando información sensible antes del anuncio oficial.
verified_user Mitigación Sugerida
Añadir validación del estado de publicación en la función de generación de metadatos en app/noticia/[slug]/page.js:
if (!noticia || !noticia.publicado) { return { title: 'Noticia no encontrada | GaamaTV', description: 'GaamaTV — El lente editorial del Oriente Antioqueño.', } }
