🧩 Detalles de Vulnerabilidades Resueltas

Archivo: app/admin/setup/page.js

Estado: Vulnerabilidad CRÍTICA mitigada. Se ha eliminado por completo la ruta y el archivo que permitía el registro público no autorizado.

Riesgo: BAJO

Recomendación a futuro: Mantener la creación de usuarios administrativos exclusivamente a través del panel backend oficial de Supabase. El ingreso al admin panel ahora requiere un usuario válido provisto por los dueños.

Archivo: supabase-rls-secure.sql

Estado: Al eliminar la puerta de registro público, las políticas de seguridad basadas en el estatus `authenticated` se vuelven seguras de facto en este modelo de plataforma exclusiva para editores (admins). Ningún usuario ajeno a los permitidos en Supabase podrá mutar datos.

Riesgo: BAJO

Recomendación a futuro: Si alguna vez la página web incorpora un sistema de inicio de sesión para el público general, se deberán migrar las políticas de RLS para chequear una tabla o flag específico de "es_admin".

Archivo: Componentes en app/admin/...

Problema Restante: Toda la lógica de administración y actualización a la base de datos se maneja del lado del cliente (`use client`), exponiendo la estructura de consultas e interactuando directamente mediante el cliente web.

Riesgo: MEDIO

Recomendación: Como no representa un riesgo crítico inminente para la data gracias al RLS y Auth privado, puede resolverse a futuro migrando gradualmente operaciones a Server Actions en Next.js.
